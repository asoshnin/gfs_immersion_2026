Set up your own Google search key

The hub can fall back to a live web search when its local knowledge base has no answer. You bring your own Google credentials — they are stored in this browser only and are sent only to googleapis.com, never to this site. This takes about 5 minutes.

Free tier: 100 searches per day, no billing required.

  1. 1 Create a search engine

    Open the Programmable Search Engine control panel.

    • Name it anything, e.g. GFS Immersion Hub.
    • Under What to search, use Sites to search and add the domains below — one per line. Do not use commas. 
    cloud.google.com/*
developers.google.com/*
ai.google.dev/*
codelabs.developers.google.com/*
firebase.google.com/*
github.com/*
adk.dev/*

    Google removed the “search the entire web” option for new engines in January 2026, and caps an engine at 50 domains. These seven are the official documentation sources this hub trusts.

  2. 2 Turn on SafeSearch

    In the same screen set SafeSearch → On. The hub requests filtered results, so this keeps them consistent.

  3. 3 Copy the Search engine ID

    Complete the reCAPTCHA and click Create. On the next screen find Search engine ID — a short string like a1b2c3d4e5f6g7h8i — and copy it.

    Ignore the code snippet Google offers for embedding a search box. This hub queries the API directly; you do not need to paste anything into a web page.

  4. 4 Create an API key

    Go to APIs & Services → Credentials in your Google Cloud project and click Create credentials → API key.

    • If Custom Search API is not enabled yet, enable it first under APIs & Services → Library.
    • Under API restrictions, choose Custom Search API — this makes the required “API selection required” error go away.
    • Under Application restrictions, leave None. The key is used from each visitor’s browser, so a website restriction would break it for everyone else.

    Copy the key — it starts with AIza.

  5. 5 Paste both values here

    Close this guide and enter the two values in the Live-web fallback section of the Keys dialog.

    Tip: testing the pair in a browser tab is the fastest way to confirm it works. Replace KEY and CX below and open the URL. 

    https://www.googleapis.com/customsearch/v1?key=KEY&cx=CX&q=test

    A JSON response with an items array means both values are good. 403 means the API is not enabled on that project; 400 means the key or engine ID is wrong.

What leaves your browser. Your search key goes only to googleapis.com. Your question is truncated to 256 characters before it is sent to Google. To show you the full content of a result page (the browser cannot read those sites directly), the page address — not your key and not your question — is sent to this hub to retrieve the public text. Nothing is stored on the server.
Heads-up on Google’s roadmap. Google closed the Custom Search JSON API to new customers in January 2026 and will discontinue it on 1 January 2027. This feature will need a different search provider after that date.
